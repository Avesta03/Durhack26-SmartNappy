# SmartNappy (aka DrySense) 💧
## Smart sensing and performance analytics for absorbent hygiene products

> **A prototype low-cost sensing platform for detecting moisture events in absorbent hygiene products and translating sensor data into actionable insights for caregivers and product developers.**

---

## The Challenge

This project was developed in response to the challenge:

> **“Understand product performance through novel sensor approaches in baby/fem.”**

Absorbent hygiene products perform a complex task: they must rapidly manage repeated liquid events while maintaining a dry and comfortable skin-facing environment.

However, product performance is often difficult to observe dynamically. A caregiver may only know that a product needs changing after manually checking it, while product developers may require controlled laboratory testing to understand how liquid interacts with different regions and layers of an absorbent product.

**DrySense explores whether low-cost embedded sensing can provide a new source of real-time data.**

The project investigates two connected applications:

1. **Consumer-facing monitoring** — detecting moisture events and providing useful information that could support caregivers' changing decisions.
2. **Product-performance analytics** — using sensor measurements to investigate how an absorbent product responds dynamically to controlled wetting events.

---

# The Idea

The original concept was simple:

> **Could a sensor inside or alongside a nappy detect when a wetting event has occurred and notify a parent?**

The idea was then expanded to ask a more interesting question:

> **What can the data generated by a moisture sensor tell us about the dynamic behaviour of an absorbent hygiene product?**

Rather than treating the sensor as a simple binary **wet/dry switch**, DrySense treats moisture as a time-series signal.

By continuously recording sensor readings, the prototype can potentially identify:

- Baseline conditions.
- Changes associated with incoming moisture.
- Individual wetting events.
- Peak sensor response.
- The persistence of elevated moisture readings.
- Changes in response following repeated liquid events.

This creates a foundation for both a potential **smart caregiver product** and a **data-driven product-development tool**.

# Prototype

The current prototype consists of:

- **Arduino UNO Q**
- **DFRobot Moisture Sensor V2**
- **Disposable nappy**
- **MacBook Pro for programming, data collection and analysis**
- Female-to-female jumper cables

The Arduino continuously reads the analogue output of the moisture sensor and sends measurements to a connected computer through the serial interface.

The prototype is positioned to investigate whether a sensor could monitor the region of an absorbent product most likely to experience a wetting event.

# How It Works

The DrySense system follows a simple data pipeline:

```text
Moisture event
       ↓
DFRobot moisture sensor
       ↓
Arduino analogue measurement
       ↓
Signal filtering and processing
       ↓
Wetting-event detection
       ↓
Time-series data
       ↓
Caregiver insight / product-performance analytics
```

The sensor measures changes in its local electrical environment. These measurements are read by the Arduino as analogue values.

Because raw sensor readings can fluctuate, the system is being developed to process multiple measurements and analyse changes over time rather than relying on a single reading.

---

# Current Implementation

The first working version of DrySense continuously reads the moisture sensor and outputs measurements to the Arduino Serial Monitor.

```cpp
const int moisturePin = A0;

void setup() {
  Serial.begin(115200);
  delay(1000);

  Serial.println("Moisture sensor test started");
}

void loop() {
  int moistureValue = analogRead(moisturePin);

  Serial.print("Moisture reading: ");
  Serial.println(moistureValue);

  delay(500);
}
```

This initial implementation successfully demonstrated that the Arduino can:

- Communicate with the DFRobot moisture sensor.
- Continuously acquire analogue measurements.
- Transmit measurements to a connected computer.
- Detect changes in the sensor's local environment.

The next stage of development expands this basic sensor test into a more sophisticated data-acquisition and event-detection system.

# Planned Signal Processing

## 1. Sensor calibration

Raw analogue readings do not automatically correspond to a universal measure of “wetness”.

The sensor must therefore be calibrated against the specific absorbent material and experimental conditions being investigated.

A calibration protocol will establish reference measurements for conditions such as:

- Sensor exposed to air.
- Sensor in contact with a dry product.
- Sensor response following controlled liquid application.

This will allow raw measurements to be interpreted as a **relative sensor response**, rather than incorrectly presenting an uncalibrated value as an absolute moisture percentage.

---

## 2. Noise reduction

Individual analogue readings may fluctuate due to electrical noise or small environmental changes.

DrySense will use repeated measurements and smoothing techniques such as a moving or exponential average to produce a more stable signal.

Conceptually:

```text
Raw readings:
1245 → 1251 → 1247 → 1258 → 1249

                ↓

Filtered signal:
1245 → 1247 → 1247 → 1250 → 1250
```

This makes it easier to distinguish meaningful changes from random variation.

---

## 3. Wetting-event detection

The system will identify a potential moisture event when the filtered sensor response changes sufficiently from its established baseline.

The detection system will eventually incorporate:

- A calibrated baseline.
- A start threshold.
- A separate stop threshold.
- Minimum event duration.
- Event timestamps.

Using separate start and stop thresholds introduces **hysteresis**, reducing the risk that small fluctuations cause the system to repeatedly switch between wet and dry states.

# Product Performance Metrics

One of the central aims of DrySense is to investigate what additional information can be extracted from continuous sensor data.

Potential metrics include:

| Metric | Description | Potential use |
|---|---|---|
| Response time | Time between liquid application and sensor response | Characterising local liquid arrival |
| Peak response | Maximum relative sensor response | Comparing controlled test conditions |
| Time to peak | Time taken to reach maximum response | Investigating dynamic behaviour |
| Response persistence | How long readings remain elevated | Investigating local moisture behaviour |
| Repeated-event response | Changes following successive liquid events | Investigating cumulative loading |
| Trial variability | Differences between repeated tests | Assessing experimental consistency |

These metrics are intended as **sensor-derived indicators**. They should not be interpreted as direct measurements of total liquid absorption, skin hydration, comfort or clinical outcomes without further validation.

# Experimental Approach

DrySense is designed around controlled and repeatable experiments.

A typical experiment could involve:

### Step 1 — Establish a baseline

Record sensor measurements under dry conditions for a defined period.

### Step 2 — Position the sensor

Place the sensor consistently relative to the absorbent material.

The position, orientation and contact pressure should be documented because these factors may influence the sensor's response.

### Step 3 — Apply a controlled liquid event

Apply a known volume of test liquid at a documented location.

### Step 4 — Record the response

Continuously collect measurements before, during and after the event.

### Step 5 — Analyse the time series

Calculate relevant metrics including:

- Initial response.
- Peak response.
- Time to peak.
- Subsequent change over time.

### Step 6 — Repeat

Repeat experiments using consistent conditions to investigate repeatability.

Future experiments could compare:

- Single large liquid events versus repeated smaller events.
- Different sensor positions.
- Different regions of the product.
- Different absorbent products or prototypes, where appropriate.

# Consumer Impact

The most immediate consumer application is a smarter alternative to a simple wetness indicator.

Instead of providing only a binary message:

> **“Wet.”**

A future DrySense-enabled system could provide context based on the history of sensor measurements:

🟢 **Dry** — No significant change detected.

🟡 **Moisture detected** — A recent sensor change has been identified.

🟠 **Monitor** — Elevated readings have persisted or repeated events have occurred.

🔴 **Consider changing** — A sustained or cumulative sensor response suggests the product may require attention.

This approach could help caregivers make more informed changing decisions.

A future implementation could communicate this information through a phone application or connected device.

**Importantly, this prototype does not currently provide health advice or guarantee when a product should be changed.** Any consumer recommendation would require substantial testing and validation.

---

# Business Impact

DrySense also explores a potential new source of product-performance data.

A sensor-based experimental platform could potentially enable product teams to:

### Quantify dynamic product behaviour

Continuous measurements can capture how sensor response changes over time rather than relying solely on before-and-after observations.

### Compare controlled test conditions

Identical liquid volumes and experimental protocols could be used to compare sensor-response profiles.

### Investigate repeated loading

Real-world absorbent products experience repeated events. Time-series sensing could provide a way to investigate how local sensor responses change following successive controlled liquid applications.

### Accelerate prototype iteration

A low-cost sensing approach could potentially complement existing product testing by providing rapid experimental feedback during early-stage development.

The longer-term opportunity is to create a feedback loop:

```text
Product testing
      ↓
Sensor data
      ↓
Performance analytics
      ↓
Product insight
      ↓
Improved product design
      ↓
Better consumer experience
```

# Limitations

This is an early-stage proof of concept.

Several important limitations should be recognised:

- The moisture sensor was not originally designed specifically for monitoring nappies.
- Sensor readings depend on placement, surrounding materials and environmental conditions.
- A local sensor measurement does not represent the moisture state of an entire product.
- Sensor response should not automatically be interpreted as total liquid absorption or skin wetness.
- The prototype has not been tested or validated for use on infants.
- The system is not a medical device and does not provide medical advice.

These limitations are not simply constraints; they identify important directions for future research and product development.

Potential future improvements include:

- Multiple distributed sensors.
- Flexible or printed sensing elements.
- Wireless communication.
- Miniaturised electronics.
- Improved calibration.
- Machine-learning models trained on larger experimental datasets.
- Integration with product-specific sensing materials.

# Why DrySense?

The core idea behind DrySense is simple:

> **Absorbent hygiene products already contain a wealth of information about how they are performing. The challenge is finding practical ways to measure and use it.**
